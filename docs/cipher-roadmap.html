P5
AI Intelligence Layer
Fully wire the AI swarm, pattern recognition, and backtesting. Make the intelligence engine real, not demo scaffolding.
In Progress
5A — Swarm Simulation (Full Wire-Up)
🔲simulation/swarm_engine.py already exists but is partially wired . Full delivery: 6-agent GPT-4o-mini multi-agent debate: Bull Analyst, Bear Analyst, Risk Manager, Quant, Macro Strategist, Swing Trader
🔲Each agent receives: ticker, composite score, flow breakdown, signal history context, current market conditions
🔲Agents produce independent { verdict: BUY|SELL|HOLD, confidence: 0–1, reasoning: string }
🔲ensemble_runner.py aggregates votes — weighted confidence aggregation → final verdict + dissent summary
🔲Anthropic Claude fallback: ANTHROPIC_API_KEY is already in config ; route to Claude when OpenAI rate-limits or for "complex" signals (composite score between 0.60–0.70 — the grey zone)
🔲Prompt routing logic: services/ai_router.py selects GPT-4o-mini vs. Claude based on signal complexity + API health
5B — Pattern Recognition Engine (New)
🔲New file: signals/pattern_engine.py
🔲Queries signal_history table (Phase 4) for historical flow patterns per ticker
🔲Repeat-pattern detection: if the same ticker fires ≥3 BUY signals within a rolling 5-day window → REPEAT_ACCUMULATION alert
🔲Flow clustering: k-means or rule-based clustering of (contract_type, DTE bucket, premium tier, time-of-day) to identify institutional vs. retail behavior patterns
🔲Anomaly alerts: if today's flow premium for a ticker is >2× its 30-day average → UNUSUAL_FLOW flag
🔲Persists pattern events to new pattern_alerts Supabase table (005_pattern_alerts.sql)
🔲GET /api/patterns/{ticker} — returns historical pattern summary + current alert flags
5C — Backtesting Module (New)
🔲New module: signals/backtester.py
🔲Replays signal_history rows chronologically — simulates entering a position at signal_ts price (fetched from Tradier historical quotes)
🔲Calculates per-signal P&L at 1-day / 3-day / 5-day exit horizons
🔲Aggregates: overall win rate, avg return, Sharpe-like ratio, best/worst ticker, drawdown
🔲GET /api/backtest/run?ticker=AAPL&start_date=2026-01-01 — runs on-demand backtest
🔲GET /api/backtest/summary — aggregated performance stats across all persisted signals
🔲Results persisted to backtest_results table for caching (don't re-run if < 24h old)
5D — Wire trade_executor.py into Signal Flow (B-009)
🔲execution/trade_executor.py exists but is disconnected
🔲Wire into async_bus fan-out — new channel "execution" subscribed by trade_executor.py
🔲Execution mode controlled by config: EXECUTION_MODE = paper | live | disabled
🔲In paper mode: writes to paper_trades table (no real orders placed)
🔲In live mode: calls Tradier order placement API (gated by execution_enabled feature flag — introduced properly in Phase 6 Admin)
🔲Risk guard: max single trade size cap (MAX_TRADE_PREMIUM env var), reject if composite < 0.75
5E — Close Mocked Endpoints (B-012, B-013, B-008)
🔲Wire GET /api/flow/scan → live Supabase query against flow_events (paginated, filterable by ticker, contract type, date range)
